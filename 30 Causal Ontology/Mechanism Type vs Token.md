# Mechanism Type vs Token

Distinguish a reusable **mechanism type** (for example, threat-induced preventive expansion) from a particular historical **mechanism token** (the process alleged to have operated in one state during one interval).

Questions: what makes two process instances tokens of the same type; which elements may vary while type identity is preserved; whether a mechanism type is a transition structure, functional form, causal pattern, or ontology class; and whether one token can instantiate multiple overlapping types.

This distinction affects identity, cross-case comparison, generalization, causal abstraction, ontology design, and evidentiary requirements.
